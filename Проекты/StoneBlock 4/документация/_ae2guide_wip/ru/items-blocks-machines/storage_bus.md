# Шина хранения

<GameScene zoom="8" background="transparent">
<ImportStructure src="../assets/blocks/storage_bus.snbt" />
</GameScene>

Вам когда-нибудь хотелось *сохранить* своего монстра из сундуков, вместо того чтобы заменить его чем-то разумным? Представляем Шину хранения!

Шина хранения превращает инвентарь, которого она касается, в [сетевое хранилище](../ae2-mechanics/import-export-storage.md).
Она делает это, позволяя сети видеть содержимое этого инвентаря и помещая в этот инвентарь и извлекая из него,
чтобы выполнять помещение [устройств](../ae2-mechanics/devices.md) в сетевое хранилище и извлечение из него.

Из-за философии AE2 возникающих механик через взаимодействие функций [устройств](../ae2-mechanics/devices.md), вам не
обязательно *нужно* использовать шину хранения для *хранения*. Используя [подсети](../ae2-mechanics/subnetworks.md),
чтобы сделать шину хранения (или несколько шин хранения) *единственным* хранилищем в сети, вы можете использовать её как источник или место назначения
для передачи предметов. (см. [«трубную подсеть»](../example-setups/pipe-subnet.md))

ВАЖНОЕ ПРИМЕЧАНИЕ: большие оптимизированные инвентари, например ящики, — нормально, но большие *не*оптимизированные инвентари с большим числом слотов, например
колоссальные сундуки, ужасны для производительности при использовании с шинами хранения.

Это [подчасти кабелей](../ae2-mechanics/cable-subparts.md).

## Фильтрация

По умолчанию шина будет хранить всё. Предметы, вставленные в её слоты фильтра, будут работать как белый список, только
разрешая хранить эти конкретные предметы.

Предметы и жидкости можно перетаскивать в слоты из JEI/REI, даже если у вас на самом деле нет такого предмета.

Щёлкните правой кнопкой контейнером с жидкостью (например, ведром или жидкостным баком), чтобы задать эту жидкость фильтром вместо предмета ведра или бака.

## Приоритет

Приоритеты задаются щелчком по гаечному ключу в правом верхнем углу интерфейса.
Предметы, входящие в сеть, сначала направляются в хранилище с наивысшим приоритетом как
в первое место назначения. В случае двух хранилищ с одинаковым приоритетом,
если одно уже содержит этот предмет, оно будет предпочтительнее любого
другого. Любые отфильтрованные хранилища в той же группе приоритетов считаются уже содержащими предмет.
Предметы, удаляемые из хранилища, будут
удаляться из хранилища с наименьшим приоритетом. Эта система приоритетов означает, что при вставке и удалении предметов
из сетевого хранилища хранилища с высоким приоритетом будут заполняться, а с низким — опустошаться.

## Настройки

*   Шину можно разделить (отфильтровать) по тому, что сейчас находится в смежном инвентаре
*   Сети можно запретить или разрешить видеть предметы в смежном инвентаре, которые шина не может извлечь
    (например, шина хранения не может извлечь предметы из центрального входного слота <ItemLink id="inscriber" />)
*   Шина может фильтровать и при вставке, и при извлечении, или только при вставке
*   Шина может быть двунаправленной, только на вставку или только на извлечение

## Улучшения

Шина хранения поддерживает следующие [улучшения](upgrade_cards.md):

*   <ItemLink id="capacity_card" /> увеличивает количество слотов фильтра
*   <ItemLink id="fuzzy_card" /> позволяет шине фильтровать по уровню урона и/или игнорировать NBT предметов
*   <ItemLink id="inverter_card" /> переключает фильтр из белого списка в чёрный
*   <ItemLink id="void_card" /> уничтожает вставленные предметы, если смежный инвентарь полон; полезно, чтобы фермы не забивались. Будьте осторожны при разделении этого!
