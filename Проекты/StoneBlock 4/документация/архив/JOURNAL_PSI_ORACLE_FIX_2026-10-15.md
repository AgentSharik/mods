# Журнал: краш игры из-за книги Psi в Oracle Index — диагноз и исправление

Дата: 2026-10-15. Мод: `Psi-neoforge-1.21.1-110.jar` (сборка StoneBlock 4), `oracle_index-neoforge-1.4.0.jar`.

## Жалоба

После переноса книги «Энциклопедия Псионики» из Patchouli в Oracle Index (штатная книга при этом сохранена) игра стала крашиться.

## Диагноз (по исходникам Oracle Index, ветка 1.21.1 = версия 1.4.0 — та же, что установлена)

Перенос был сделан в **устаревшем (legacy) формате** вики: страницы лежат в `assets/oracle_index/books/psi/.content/…`, а `sinytra-wiki.json` без поля `schema`. Цепочка краша:

1. Oracle Index регистрирует `SynchronousResourceReloader` на клиентские ресурсы: при каждом релоаде (старт игры, F3+T) `DocsIndexer.findAllResourceEntries` индексирует все `.mdx` под `books/`.
2. Без `schema: "1"` вика опознаётся как legacy; пути с `/.content/` — режим CONTENT.
3. Для контентных страниц индексатор читает YAML-frontmatter: `frontmatter.getAll("id")`. У всех 55 перенесённых страниц frontmatter отсутствует полностью (вместо него в текст вставлен HTML-комментарий `<!-- icon: … -->`), поэтому `getAll` возвращает `null`.
4. `computePageRef(...)` сразу вызывает `ids.size()` → **NullPointerException**. В `processEntry` перехватывается только `IOException`, NPE вылетает из reload-listener'а — клиент крашится на загрузке ресурсов.

Проверено статически: 55 из 55 страниц без `id`; 54 из них — в `/.content/`.

Не виноваты: сама книга Patchouli (в JAR не тронута, сверено с исходником побайтово по CRC), ru_ru, патчи классов конфига (в Psi изменены только 2 класса конфига и только строки-комментарии).

## Исправление (согласован вариант V1)

Книга переведена в актуальный формат V1 — как эталонная книга самого Oracle Index:

- `sinytra-wiki.json`: добавлен `"schema": "1"` (сохранены id и платформы).
- Страницы перенесены из `.content/<раздел>/` в `docs/<раздел>/`; страницы разделов (`_category.mdx`) стали `category.mdx` первыми в своих разделах.
- Все `_meta.json` переписаны объектами `{"name": …, "icon": null}`; корневой `docs/_meta.json` перечисляет введение и 4 раздела.
- Каждой странице добавлен YAML-frontmatter `title:` с русским названием.
- Старые legacy-файлы (`.content/**`, корневой `_meta.json`) удалены. Штатная книга Patchouli на месте и не изменена — доступна, как и требовалось: она нужна для изучения заклинаний.

## Проверка

- Симуляция логики 1.4.0 по новому JAR: формат V1, контентных страниц (где нужен `id`) — 0, то есть краш-путь недостижим; дерево навигации от `/docs` полное, все страницы на месте (55 .mdx); testzip чистый.
- Сверка с исходным Psi: вне oracle-книги изменения те же, что были (ru_ru + 2 класса конфига).
- Счётчики README/RELEASE не изменились (ключи не добавлялись), `update_readme_stats.py --check` чистый.

Запуска в игре не было; проверка статическая. Если после этого краш повторится — нужен crash-report: по этому пути он больше невозможен, значит, причина будет другой.
