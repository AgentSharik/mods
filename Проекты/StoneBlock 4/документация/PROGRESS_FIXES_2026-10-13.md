# Исправления после проверки тестового релиза — 13.10.2026

Замечания по итогам проверки в игре и повторный аудит готовых JAR. Каждый мод закрывался
отдельным коммитом и пушем; здесь — сводка пачки.

## Что было найдено

1. **Повреждённый английский в готовых JAR.** У 35 из 89 пар `en_us/ru_ru` в готовых JAR
   английский файл побайтово совпадал с русским: при прошлых сборках `en_us.json` был
   перезаписан русским текстом, а часть прочих языков потеряна. Подлинный английский есть
   только в исходниках (`Исходные моды для перевода/`), поэтому JAR пересобирались заново
   из исходников: русский перевод взят из готового JAR, относительно исходника меняется
   только `ru_ru.json` и добавляются русские файлы книг/гайдов, которых в исходнике нет.
2. **Один ложный положительный результат.** У `apothic_compats-0.2.4.3.jar` `en_us.json`
   и в исходнике содержит русский текст (так выпущен сам мод): готовый JAR побайтово
   совпадает с исходником по всем записям, править нечего.
3. **MFFS.** В готовом JAR русские книги уже были (Patchouli — 49 статей, Oracle Index —
   44 `.mdx`), но основной lang был повреждён (см. п. 1), а в интерфейсе и книгах оставались
   английские названия режимов. JAR пересобран из исходника с сохранением обеих книг;
   `Banned/Allowed` → «Запрещено»/«Разрешено», `Derive/Integrate` → «Извлечение»/«Интеграция»
   в lang, книге Patchouli и Oracle Index; подсказка сохранения и единицы Фортрона приведены
   к русскому виду.
4. **JEI.** В готовом JAR уже были все 311 ключей `en_us` и 312 ключей `ru_ru`, пропусков 0,
   английский не повреждён. Английским оставались имена режимов в описаниях настроек
   (`RECTANGULAR`, `PAGED`, `AUTO_HIDE` и т. п.) и глаголы `Hold/Press` в подсказках —
   описания переписаны по-русски, подсказки приведены к «Удерживайте»/«Нажмите», JAR
   пересобран из исходника. Значения выпадающих списков на экране Configured сам Configured
   строит из имён enum (`Component.literal`), языковыми файлами JEI они не переводятся;
   отладочные тестовые строки JEI оставлены как в оригинале.
5. **Collapsible Groups.** Готового JAR не было. Переведены все 361 ключ: настройки,
   менеджер групп, редактор, правила фильтров, диалоги и подсказки для EMI/JEI. JAR собран
   из исходника (в исходнике русского файла нет, добавлен только `ru_ru.json`).

Красная строка «Model and Texture still work in progress…» в Ars Elemental языковыми
файлами не исправляется: это `Component.literal(...)` в классах брони. Патч классов —
отдельное решение, в эту пачку не входит.

## Дополнение (тот же день, по повторной просьбе): Ars Elemental и значения JEI

- **Ars Elemental — красная строка исправлена патчем классов.** Константа
  «Model and Texture still work in progress, currently same as medium variant.»
  в `HeavyArmorE.class` и `LightArmorE.class` заменена на «Модель и текстура ещё
  в разработке — пока такие же, как у среднего варианта» (`scripts/patch_class_string.py`,
  меняется только Utf8-константа constant pool). JAR пересобран из исходника: изменены
  только `ru_ru.json` и эти два класса. Воспроизведение — `_ae_wip/CLASS_PATCH.md`.
- **JEI — значения настроек переведены.** Добавлен 61 ключ `jei.config...<настройка>.<значение>`
  (режимы поиска, сетка ингредиентов/закладок, режим выдачи, сторона истории, этапы
  сортировки, функции подсказок): по таким ключам экраны конфигурации ищут названия
  значений, в оригинале их нет. Всего в `ru_ru.json` теперь 373 ключа.
- **Что осталось за пределами JEI.** Экран настроек JEI рисует мод **Configured**: подписи
  он строит из внутренних имён полей JEI, а список значений enum — из имён enum
  (`JeiValue.getTranslationKey()` в Configured возвращает null, подписи значений —
  `Component.literal(...)`), поэтому часть подписей на том экране языковыми файлами JEI
  не переводится в принципе. Лечится патчем двух классов самого Configured
  (`JeiValue`, `ChangeEnumScreen`) и его 10 недостающими русскими ключами; для этого нужен
  файл `configured-neoforge-1.21.1-*.jar` из папки модов сборки — в проекте его нет,
  а релизные JAR Configured снаружи песочницы не скачиваются.

## Дополнение 2 (тот же день): экран JEI рисует не Configured, а Carbon Config — исправлено

Предыдущее дополнение исходило из того, что экран настроек JEI рисует Configured.
Проверка по факту это не подтвердила; кто рисует экран, установлено по коду:

- **ConfiguredDefaults — не тот мод.** Файл из папки модов
  (`ConfiguredDefaults-v21.1.3-1.21.1-NeoForge.jar`, добавлен в исходники) оказался
  модом Fuzs на 43 КБ: копирует заготовленные файлы в папку игры, экранов и
  языковых файлов не имеет, переводить в нём нечего.
- **Внутри JEI пусто.** В `jei-1.21.1-neoforge-19.54.0.429.jar` нет ни вложенных
  JAR, ни классов экрана; `ConfigHelper` делегирует экран
  `IConfigScreenFactory.getForMod("jei")`, а `en_us.json` самого JEI содержит
  `jei.jei.configured` = «Install the "Configured" mod to access the
  in-game config».
- **Провайдер — Carbon Config.** В исходниках сборки нашёлся
  `CarbonConfig-Neoforge-1.21.1-2.0.2.1.jar`: в нём плагин
  `carbonconfiglib/plugins/jei` берёт конфиги JEI через `IJeiConfigManager` и
  рисует их собственным экраном Carbon. Подписи настроек локализованы JEI,
  английскими оставались: имена категорий (`createLabel` из сырого имени) и
  значения enum (`Suggestion.value(...)` → литерал имени константы).

Сделано по CarbonConfig (коммит одним модом, JAR + описание патча
`_carbonconfig_wip/CLASS_PATCH.md`, снапшот `ru_work.json`):

- **Патч байткода** (`scripts/patch_carbon_jei.py`, JDK в песочнице нет): в
  `JEIHelpers` добавлены `localizeEnumSuggestions` (имя показа enum — перевод
  JEI по ключу `<настройка>.<enum_lowercase>`, те 61 ключ из предыдущего
  дополнения; сериализованное значение не меняется, сохранение цело) и
  `jeiCategoryLabel` (ключи `jei.config.client./colors./debug./modIdFormat.` +
  имя, иначе прежний `createLabel`); `JEIValue.getSuggestions`,
  `JEIArray.getSuggestions` и `JEINode.getName` проксируют через них. Прочие
  методы и поля — байт-в-байт как в оригинале (проверено сравнением),
  constant pool только дописан.
- **Перевод доведён до 180/180**: существующие 112 ключей интерфейса вычитаны
  (правок не потребовалось), добавлены 68 ключей `legacy.gamerule.*`
  встроенного экрана игровых правил Carbon.
- JAR пересобран из исходника: изменены только `ru_ru.json` и 4 класса
  плагина, вложенный Primitive Collections не тронут, `testzip` чист.
  sha256: `90e5891eb072cfee9fa339e27ce8f11e55cfb1d6633064731ce722ac56a23323`
- **Итого по сборке: 96 готовых JAR, 40 152 ключа.**
- Проверка в игре не выполнялась: нужны замена JAR в папке модов и взгляд на
