# Как переводить моды Minecraft 1.21.1 на русский

Полное описание конвейера: от распаковки модпака до публикации релиза.
Каждый шаг можно повторить ровно так, как здесь написано.

---

## 0. Главные правила (нарушать нельзя)

1. **Уже переведённое не трогаем.** Если у мода есть `ru_ru.json` с русским —
   этот мод дозаполняется, а не пересобирается. Перезапись чужого перевода
   ломает то, что люди уже поставили.
2. **Русский — основной язык.** В каждом собранном моде:
   - `ru_ru.json` содержит перевод;
   - `en_us.json` **продублирован русским** (это фолбэк для любого языка игры,
     иначе у игроков с другим языком будет английский);
   - прочие языки удаляются.
3. **Терминология — строго по ванильному `ru_ru.json`.** Не из палитров
   переводов, не из интернета, не «как красивее». Если слово есть в ванилле —
   берём ванильный вариант.
4. **Перевод должен звучать как в игре.** Не как переводческое бюро.
   `Right Click` → `ПКМ`, а не «Правый клик». `Chest` → `Сундук`, а не «Грудь».
5. **Технические слова остаются латиницей.** Единицы, бренды, идентификаторы,
   форматные шаблоны. Ниже точный список.
6. **Тексты команд не трогаем вообще.** `\time set day`, `\give @s stone`,
   `forge:experience` — это синтаксис, он должен остаться байт в байт.
7. **Идентификаторы ресурсов не меняем.** В документации нельзя трогать:
   `icon:`, `id=`, `location=`, `parent:`, `item_ids:`, `slots={...}` —
   по ним мод ищет ассеты.
8. **Если нормального перевода нет** — русская транслитерация
   (`Archi` → `Арчи`) или максимально похожий аналог. Но не выдумывать.
9. **Каждая партия — отдельный релиз.** В архив попадают только изменённые моды.

---

## 1. Что переводим в моде

| Что | Файлы | Примечание |
|---|---|---|
| Названия | `assets/<modid>/lang/en_us.json`, ключи `block.*`, `item.*`, `fluid.*`, `entity.*` | Короткие строки |
| Проза | те же ключи, остальные | Тултипы, подписи конфигов, описания |
| Документация | `*.md`, `*.mdx` внутри JAR | Видна прямо в игре (Oracle Index и т.п.) |

Один и тот же мод может отдавать фразы **другому моду** (например, зависимость
тянет свою папку с документацией). Искать английский надо по всему JAR,
а не только по своему `modid`.

## 2. Подготовка

```bash
python3 getpack.py                 # скачивает mods.zip (660 МБ) и распаковывает
ls /home/user/dl/pack/mods | wc -l # должно быть 414
```

Архив пропадает из песочницы между сессиями — это нормально, качать заново.
Скачанный архив: `dl/mods.zip`, распакованные моды: `dl/pack/mods/*.jar`.

### Триаж: что вообще переводить

```bash
python3 triage.py
```

Пишет `dl/triage.csv` и считает по каждому моду:

| Категория | Что значит | Действие |
|---|---|---|
| `RU_FULL` | есть `ru_ru.json` и он весь русский | **НЕ ТРОГАТЬ** |
| `RU_PART` | русский есть, но часть строк английская | дозаполнять (нужен режим `fill`) |
| `NO_RU` | русского нет вовсе | переводить с нуля |
| `NO_LANG` | lang-файлов нет (библиотеки) | не трогать |

Берём партиями по ~20 модов. Сначала `NO_RU` — для них сборка безопасна.
`RU_PART` — только после того, как написан режим `fill` (см. раздел 9).

## 3. Словарь

`words_ru.py` — основной словарь.

```python
WORDS = {
    'bamboo': 'бамбук',      # существительные
    'planks': 'доски',
    'save':   'Сохранить',   # игровые кнопки и подписи
}
KEEP = {...}                # латиница всегда: shift, ctrl, cf, fe, rf…
```

`mp_tr.py` — движок перевода. Ключевые таблицы:

- `NOUN` — существительные с родом и числом: `('блок', 'm', 'sg')`
- `ADJ` — прилагательные с формами по роду и падежу
- `ADJ_STEM` — основы материалов: `bamboo → бамбуков`
- `NOUN_GENDER` — существительное → род (`доска: f`, `блок: m`, `стекло: n`)
- `VANILLA` / `VANILLA_SINGLE` — ванильные переводы
- `CLICK_PHRASES` — `Right Click → ПКМ`, `Left Click → ЛКМ`, `Middle Click → СКМ`
- `MATERIAL_NOUN` — `мангровое дерево → мангров`
- `INTENTIONAL` (в `lang_overrides.py`) — ключи, которые намеренно латиницей

### Как проверить словарь

```bash
python3 measure_names.py    # ищет неизвестные слова в названиях
```

Цель — `уникальных неизвестных: 0`.

### Как правильно добавлять слово

```python
# 1. Открыть words_ru.py, найти WORDS = {
# 2. Добавить пару: ключ — английское слово в нижнем регистре,
#    значение — русский перевод.
WORDS = {
    ...
    'quartz': 'кварцевый',   # прилагательные тоже сюда, нижний регистр
}
```

**Важно:** движок ищет по `w.lower()`, поэтому ключ всегда строчными.
Точное совпадение регистра не работает.

Материалы, которые должны стать прилагательными, добавляются в `ADJ_STEM`
в `mp_tr.py` — одной основой:

```python
ADJ_STEM = {
    'bamboo': 'бамбуков',    # → бамбуковый / бамбуковая / бамбуковое / бамбуковых
}
```

Окончания подставляются автоматически по роду, числу и падежу.

## 4. Сборка

```bash
python3 build_mp.py                      # все моды
python3 build_mp.py lychee kiwi nbtac    # только перечисленные
```

Мод с апострофом в имени (`L_Ender's Cataclysm`) ломает shell — запускать
через Python:

```python
import sys, io, contextlib, build_mp
sys.argv = ['build_mp.py'] + ['L_Ender\'s', 'lychee']
buf = io.StringIO()
with contextlib.redirect_stdout(buf):
    build_mp.main()
```

Сборщик делает: берёт `en_us.json`, переводит каждое значение через движок,
кладёт результат и в `ru_ru.json`, и в `en_us.json`, прочие языки удаляет.
Результат — в `out/`.

Часть модов отдаёт **битый JSON**; сборщик такой мод пропускает с предупреждением
и продолжает работу.

## 5. Проза

Имена движок переводит сам, а прозу — вручную, по словарю строк.

```bash
python3 party_prose.py party3.txt prose/party3.txt
```

Собирает все непереведённые фразы конкретной партии.

Перевод пишется в `prose/<имя>.ru.tsv` — TSV, **табуляция** между
английским и русским, одна строка на фразу:

```
Pose: %s	Поза: %s
<< Prev	<< Назад
Resistance: +%d%% 	Сопротивление: +%d%%
```

### Обязательные правила прозы

- **Плейсхолдеры `%s`, `%d`, `%.1f%%`, `%1$s`, `{0}` копируются дословно.**
  Ни одна цифра, ни один знак `%`, ни порядок аргументов не меняются.
- **§-коды** (`§a`, `§7`, `§e`, `§r`, `§o`, `§f`) сохраняются в правильных
  местах. `§` и `&` — взаимозаменяемые, но лучше не трогать ни тот, ни другой.
- **Форматные шаблоны сообщений не переводятся:**
  `{0,choice,1#Condition|1<Conditions}:`, `{0,choice,0#condition|1<conditions>}`.
  Это синтаксис ICU, перевод сломает вывод.
- **Идентификаторы рецептов не переводятся:** `forge:experience`, `minecraft:stone`.
- **Ключи и пробелы по краям сохраняются:** у `" Resistance: +%d%% "`
  два пробела в начале и один в конце — они часть строки.
- **Скобочные суффиксы в названиях не трогаем:** `Armz 3 (CTM)`,
  `Archim (WIP)`, `Zeon [Столб]`.

### Проверка прозы

```bash
python3 check_prose.py
```

Цель: `переведено: 415/415 = 100%` и `ошибок в переводах: 0`.

Валидатор проверяет: совпадение плейсхолдеров, §-кодов, HTML-тегов
(`<item>`, `<imp>`, `<n>`, `<r>`, `<tifisgrin>`), команд и чистую латиницу.

### Теги в прозе

Движок требует, чтобы **мультимножество тегов** в переводе совпадало
с оригиналом:

```python
sorted(TAG.findall(en)) == sorted(TAG.findall(ru))
```

где `TAG = re.compile(r'</?\w+>')`.

Если перевод «поехал», сначала сверь списки тегов, и только потом правь
текст. Автоматический reconciler тегов использовать нельзя — он портит
содержательные переводы, заменяя `<item>` на `<r>`.

## 6. Точечные подписи

Короткие служебные строки не проходят через словарь имён. Их правит
`lang_overrides.py`:

```python
OVERRIDES = {
    'info.actuallyadditions.gui.disabled': 'Отключено',
}
INTENTIONAL = {
    'misc.actuallyadditions.energy',   # CF — единица, латиницей
    'tooltip.actuallyadditions.nbt.desc',  # NBT — техническое
}
```

Скрипт правит **и `ru_ru.json`, и `en_us.json`** — иначе они разойдутся
и верификатор упадёт.

Запуск:

```bash
python3 lang_overrides.py
```

В конце должно быть `непереведённых и не намеренных: 0`.

## 7. Согласование

Русский требует согласования рода, числа и падежа. Движок делает это
в функции `agree_ru()` — она работает **на собранной строке**, внутри
`_translate_name`, а не постфактум.

Правила:

| Что | Как |
|---|---|
| Род | `доска` (ж.р.) → `вишнёвая`; `блок` (м.р.) → `бамбуковый`; `стекло` (с.р.) → `бамбуковое` |
| Число | `кирпичи` (мн.) → `повреждённые`; `кирпич` (ед.) → `повреждённый` |
| Падеж | после предлога: `Плита из деревянного камня` |
| Головное слово | может стоять справа (`Храмовые замшелые резные кирпичи`) или слева (`Стекло скошенное фиолетовое`) |

Чтобы добавить существительное в согласование, внесите его в `NOUN_GENDER`
и, если оно склоняется, в `GEN_PL`:

```python
NOUN_GENDER = {'плитка': 'f', 'плитки': 'f', ...}
GEN_PL = {'плитки': 'плиток', ...}
```

### Типовые ошибки

| Неправильно | Правильно | Почему |
|---|---|---|
| `Плита из бамбук дощатых балок` | `Плита из бамбуковых дощатых балок` | материал — прилагательное |
| `Вишнёвый доска` | `Вишнёвая доска` | род по существительному |
| `Костная блок` | `Костный блок` | род по существительному |
| `§bлиния` | `§bЛиния` | §-код задаёт цвет, а не регистр |
| `пКМ` | `ПКМ` | аббревиатура не переводится регистром |
| `Правый нажмите` | `ПКМ` | клик-фраза не разбивается на токены |

## 8. Проверка и релиз

```bash
python3 verify_mp.py     # 0 проблем со структурой
python3 audit_dict.py    # латиница, дубли, порядок слов
python3 make_release.py  # ZIP + README.md + sha256.txt
```

`verify_mp.py` обязателен: он единственный видит **фактическое** состояние
JAR. Внутренний счётчик `build_mp.py` показывает процент по правилам движка
и всегда ниже.

### Что означает «100%»

Считать надо так:

- **Проза** — `415/415 = 100%`, `ошибок 0`. Это настоящие 100%.
- **Названия** — 100% означает «0 неизвестных слов», а не «0 строк без
  кириллицы». Строки вроде `CF`, `RF`, `I/O`, `%s`, `forge:experience`
  обязаны остаться латиницей.

Честная формулировка для README: «из N строк на русском M, остальные —
единицы, бренды и форматные шаблоны, которые переводить нельзя».

### Релиз

`make_release.py` берёт всё, что лежит в `out/`. Перед запуском убедитесь,
что в `out/` только нужная партия (`rm -rf out && mkdir out`).

## 9. Режим `fill` — для частично переведённых модов

**Не используйте `build_mp.py` на `RU_PART` модах.** Он берёт `en_us.json`
как основу и перезаписывает `ru_ru.json` целиком, затирая чужой перевод.

Проверено на `enderdrives`: из 57 русских строк 6 хороших переводов
превратились в английские.

```python
# псевдокод правильной логики
existing = json.load(open('ru_ru.json'))      # основа
en       = json.load(open('en_us.json'))
for k, v in en.items():
    if k in existing and CYR.search(existing[k]):
        continue                              # русский есть — НЕ ТРОГАЕМ
    existing[k] = translate(v)                # дозаполняем
```

Перед выпуском релиза обязательно прогнать сверку:

```python
# сколько ключей потеряли русский
lost = [k for k, v in old_ru.items()
        if CYR.search(v) and not CYR.search(new_ru.get(k, ''))]
assert not lost, lost
```

Такой скрипт надо встроить в `verify_mp.py`, чтобы регрессия не могла
пройти молча.

## 10. Документация `.md` / `.mdx`

В модпаке есть моды с встроенной документацией — в вашем эталоне
`simplyswords` содержит 153 таких файла (~50 000 символов). Они видны
прямо в игре.

Правила те же, что для прозы, плюс:

- **не менять** `icon:`, `id=`, `location=`, `parent:`, `item_ids:`,
  `slots={...}` — это ключи поиска ассетов;
- YAML-структуру сохранять, переводить только значения;
- код внутри ``` … ``` не трогать.

Сборщик сейчас это **не делает** — в партии 3 попал только один
`changelog.md` из xycraft, и он остался английским. Это надо доделать,
чтобы scope `full` был честным.

## 11. Публикация

Токен GitHub хранить **только во временном файле вне рабочей папки**:

```bash
cat > /tmp/.gh_token <<'EOF'
github_pat_...
EOF
chmod 600 /tmp/.gh_token
```

Никогда не класть токен в workspace — он попадёт в коммиты.

```python
import urllib.request, json, base64
tok = open('/tmp/.gh_token').read().strip()

# создать релиз
POST /repos/AgentSharik/mods/releases
{'tag_name': 'ru-batch-3', 'name': 'Партия 3', 'body': README}

# вложить файлы — отдельный хост
POST https://uploads.github.com/repos/AgentSharik/mods/releases/<id>/assets?name=<файл>

# обновить README.md в папке — обязательно с sha существующего файла,
# иначе 422
PUT /repos/AgentSharik/mods/contents/ru_1.21.1/README.md
{'message': '...', 'content': base64(...), 'branch': 'main', 'sha': <текущий sha>}
```

`curl -d` для больших файлов даёт `Argument list too long` — использовать
`urllib.request`.

## 12. Регулярные проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `моды не найдены` | пропал `dl/pack/mods` | `python3 getpack.py` |
| `JSONDecodeError` при сборке | мод кладёт битый `en_us.json` | сборщик теперь пропускает с предупреждением |
| Мод с апострофом не собирается | ломает shell | запуск через Python, `sys.argv` |
| `ru_ru и en_us различаются` | оверрайд применён только к одному файлу | `lang_overrides.py` правит оба |
| Счётчик не меняется после правки | пакет пропал, сборка молча ничего не сделала | всегда смотреть вывод `build_mp.py` |
| `IndexError` в `mp_tr.py` | регуляркой задеты чужие таблицы | откат из git: `git checkout mp_tr.py` |
| Пробелы «съехали» | в TSV попали не табы | разделитель — строго `\t` |

**Главное правило работы с кодом:** после каждой правки гонять точечные
проверки, а не только смотреть на итоговый процент. Регулярки по исходникам
движка уже дважды ломали чужие таблицы.
